# Zapbar 6c: widgets on iOS, and 1.2.0 on both stores — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** iPhone gets the two Zapbar widgets Android has: Volume, and Remote with the volume row plus four inputs. Taps act on the soundbar. Then 1.2.0, carrying these widgets and Plan 6b's tips, ships on Play and the App Store.

**Architecture:**
- A WidgetKit extension (`app.zapbar.remote.widgets`, iOS 17) is generated by `@bacons/apple-targets` from `apps/remote/targets/widgets/`. `ios/` stays generated.
- The app and the extension share the App Group `group.zapbar.app`:
  - the app's `ZapbarQuick` Swift module writes the config JSON (`buildQuickConfig`, unchanged) and a new last-state JSON into it, then reloads the widget timelines;
  - the extension reads both.
- The extension's buttons are `AppIntent`s that run a Swift port of `QuickActions.kt`, `HeosLite.kt` and `HeosCodec.kt`. That port is the `QuickCore` folder. A SwiftPM package on the Mac tests it.
- Task 2's network test decides whether the intents talk to the bar directly or open the app (Task 5).

**Tech Stack:**
- Swift 6, WidgetKit, AppIntents, Network.framework (`NWConnection`);
- `@bacons/apple-targets`;
- Expo SDK 58 config plugins;
- SwiftPM `swift test` on the Mac mini (Xcode 27.1);
- the existing headless TestFlight pipeline.

**Spec:** `docs/specs/2026-10-18-zapbar-ios-design.md`:
- §6 (widgets) and §8 step 0, the widget network test, which becomes Task 2 here and is built into the real code rather than thrown away;
- §7 (build and release).

Related: Plan 6b, `docs/plans/2026-10-20-zapbar-6b-ios-tips.md`.

## Global Constraints

- **Android widgets and Android behaviour stay unchanged.** The new `QuickNative.setState` is a no-op on Android. Every Kotlin test and every Jest test stays green.
- **Identifiers:**
  - App Group: `group.zapbar.app`.
  - Extension bundle ID: `app.zapbar.remote.widgets`.
  - Widget kinds: `ZapbarVolume` and `ZapbarRemote`.
  - App Group defaults keys: `config` and `state`.
- **The extension's deployment target is iOS 17.0.** The app runs without widgets on earlier versions.
- **Widget content mirrors Android:**
  - **Volume** (`systemSmall`): a 20-segment volume bar (segment i sets volume `5*(i+1)`), a mute button and the volume number. A message from the last 3 s replaces the number with "!".
  - **Remote** (`systemMedium`): the soundbar name and its status line, the same volume row, and four input buttons. The buttons follow the user's order and skip hidden inputs, and the active input is highlighted.
  - **No config:** the widget shows "Open Zapbar to set up", and a tap opens the app.
- **Status text matches Android exactly:**
  - "Open Zapbar to set up";
  - "Open Zapbar to reconnect" when the bar can't be reached;
  - "Soundbar didn't respond" on any other failure;
  - otherwise the active input's label, or an empty line.
- **The volume cap** follows `QuickConfig.capped` from `QuickStore.kt` exactly. Dad mode reaches the widget through `volumeCap`.
- **`ios/` is generated** and never hand-edited. The extension, entitlements and App Group come from `app.json` plus `targets/widgets/expo-target.config.js`.
- **Signing stays headless and manual**: two App Store profiles made through the API, "Zapbar App Store" and "Zapbar Widgets App Store".
- **Owner-only step:** create the App Group `group.zapbar.app` on developer.apple.com, then enable it on both App IDs. The API cannot create App Groups, so this comes before Task 2.
- **No data collection.** The extension talks only to the bar's `lastIp` on port 1255.

## Review Focus

1. **The bar's IP changed since the app last ran** (DHCP):
   - Expected: "Open Zapbar to reconnect" and no hang. The intent gives up within 3 s.
   - Pinned by: Task 1, test `unreachable bar gives reconnect message`, using a connect that throws `Unreachable`.
2. **A tap during a slow reply, or two quick taps:**
   - Expected: actions run one at a time, and a failure restores the state from before the optimistic paint.
   - Pinned by: Task 1, test `failure restores the state before the optimistic paint`.
3. **The user hid inputs or reordered them in the app:**
   - Expected: the Remote widget shows the first four visible inputs, in order.
   - Pinned by: Task 1, test `visibleInputs skips hidden and keeps order`; Task 3, Jest test `setState and setConfig carry the arranged inputs`.
4. **Dad mode on, and a tap on segment 20** (volume 100):
   - Expected: the volume is capped at 30, but a volume already above the cap is never raised.
   - Pinned by: Task 1, tests `segment tap is capped` and `cap never raises a volume already above it`, ported from `QuickStoreTest.kt`.
5. **Malformed or old config JSON in the App Group** (a field missing from an older app version):
   - Expected: optional fields take Android's defaults; an unreadable config counts as no config.
   - Pinned by: Task 1, tests `config without volumeCap defaults to 100` and `garbage config is nil`.

### Task 1: QuickCore, the Swift port with tests

**Files:**
- Create: `apps/remote/targets/widgets/Core/HeosCodec.swift` (port of `HeosCodec.kt`).
- Create: `apps/remote/targets/widgets/Core/HeosClient.swift`:
  - a port of `HeosLite` plus `HeosQuick`, using `NWConnection`;
  - one command at a time;
  - "command under process" extends the deadline;
  - a 3 s timeout.
- Create: `apps/remote/targets/widgets/Core/QuickModel.swift`: `QuickConfig`, `QuickInput`, `QuickState` (all `Codable`), and `Pill` math plus `status()` from `WidgetRenderer.status`.
- Create: `apps/remote/targets/widgets/Core/QuickActions.swift` (port of `QuickActions.kt`).
- Create: `apps/remote/ios-tests/Package.swift`:
  - library target `QuickCore` at `Sources/QuickCore`, a symlink to `../../targets/widgets/Core`;
  - test target `QuickCoreTests`.
- Test: `apps/remote/ios-tests/Tests/QuickCoreTests/QuickCoreTests.swift`.

**Interfaces:**
- Produces, for Tasks 2 to 5:
  - `struct QuickConfig: Codable`, with `key`, `serial`, `lastIp`, `name`, `inputs: [QuickInput]`, `volumeKeys`, `notification` and `volumeCap` (default 100). Also:
    - `static func decode(_ json: String?) -> QuickConfig?`;
    - `func visibleInputs() -> [QuickInput]`;
    - `func capped(_ target: Int, current: Int) -> Int`.
  - `struct QuickState: Codable, Equatable`, with `volume`, `mute`, `activeMid: String?`, `playState`, `message: String?` and `messageUntil: Double` (ms since 1970). Also `static func decode(_ json: String?) -> QuickState`, which falls back to `QuickState()`.
  - `enum QuickAction { case setVolume(Int), step(Int), toggleMute, playInput(String), refresh }`.
  - `protocol QuickBackend { func config() -> QuickConfig?; func state() -> QuickState; func saveState(_ s: QuickState) }`.
  - `protocol HeosQuickLike`: the same members as the Kotlin interface, with `async throws` methods.
  - `final class QuickActions`:
    - initialiser `init(backend: QuickBackend, connect: @escaping (String) async throws -> HeosQuickLike)`;
    - `func run(_ a: QuickAction, before: QuickState?) async -> QuickState`, serialised by an actor.
  - `enum Pill { static let segments = 20; static func volumeFor(_ i: Int) -> Int; static func filled(_ v: Int) -> Int }`.
  - `func status(_ cfg: QuickConfig?, _ s: QuickState, now: Double) -> String`.
  - `enum HeosClient { static func connect(_ ip: String) async throws -> HeosQuickLike }`. It throws `QuickError.unreachable` when the TCP connect fails within 3 s.
  - `enum Shared { static let group = "group.zapbar.app" }`.
  - `final class GroupBackend: QuickBackend`, which reads and writes `UserDefaults(suiteName: Shared.group)` keys `config` and `state`.
