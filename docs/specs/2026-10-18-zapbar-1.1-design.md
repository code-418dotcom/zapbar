# Zapbar 1.1: silly perks and Play fixes (Plan 7)

**Status:** owner decided scope 2026-10-18 ("fixes plus the cheap perks, iOS gets them too"); owner skipped design questions ("use the spec"). Every call below not quoted from the owner or the release spec is marked *builder's call*.
**Parent specs:** `2026-10-17-zapbar-release-design.md` §5 (tip jar) and §10 (perk backlog), `2026-10-18-zapbar-ios-design.md` (iOS parity).

## 1. Intent

1.1 gives supporters more reasons to tip and clears the four "recommended actions" Play Console shows on 1.0.1. Nothing changes for non-supporters except the large-screen layout and the shrunk build.

**Success criteria:**
- 1.1.0 (versionCode 10100) is in production on Play.
- A supporter can switch each of the five perks on and off; a non-supporter never sees them; a refund switches them all off.
- Play Console's release dashboard for 1.1.0 no longer shows the orientation and R8 recommendations. The edge-to-edge and bitmap items are fixed where the cause is in Zapbar's code; any remainder from React Native or a library is named in the release notes of this plan.
- All existing tests pass; every perk has tests.
- The iOS spec lists the 1.1 perks under parity.

**Owner decisions (2026-10-18):**
- Perks in 1.1: 0–11 volume, pirate labels, tap the Z seven times, confetti on unmute, dad mode (release spec §10 items 1, 4, 5, 6, 7). Not alternate icons, not the retro skin.
- iOS v1 gets the same perks.
- Multi-zone is a separate app, not Zapbar.

## 2. Perks

Release spec §5 still holds: any tier unlocks every perk, and a refund reverts to defaults on the next ownership read (`Supporter.refresh` already resets `appearance` to `DEFAULT_APPEARANCE`).

**Storage** *(builder's call)*: the four switchable perks extend `Appearance` in `src/theme.ts` with `eleven`, `pirate`, `confetti`, `dad` (booleans, all `false` by default). `DeviceMemory.appearance()` validates each as a boolean and falls back to the default. This reuses the existing persistence, the supporter gate in `Supporter.setAppearance` and the refund reset.

**Settings** *(builder's call)*: the Support card, below the font picker and only for supporters, gets a "Silly perks" label and four switch rows (same `ToggleRow` look as Settings):
- "This one goes to 11"
- "Pirate labels"
- "Confetti on unmute"
- "Dad mode (max volume 30)"

The card's subline becomes: "Zapbar is free and stays free. Tips unlock a badge, extra colours and some very silly perks, nothing else." `docs/release/listing.md` gets the matching sentence.

### 2.1 This one goes to 11
- The volume number next to the slider shows `Math.round(volume * 11 / 100)` (0–11). The slider, the bar and every command keep 0–100.
- The slider's accessibility value reads the 0–11 number.
- App only: widgets, the notification and the floating slider keep 0–100 (release spec: perks apply in the app only).

### 2.2 Pirate labels
Copy only, app only. A single table in `src/ui/copy.ts` *(builder's call)* maps keys to plain and pirate text; components read it through a `useCopy()` hook that follows `appearance.pirate`. At minimum:

| Where | Plain | Pirate |
|---|---|---|
| Input tile and top card, for the ARC input while it carries its default label | TV | Arrr-C |
| Volume slider accessibility label | Volume | Hoist the volume |
| Mute button accessibility label | Mute / Unmute | Silence the parrot / Free the parrot |
| Top card empty state | Pick an input below | Pick yer port below |
| Top card banner | Reconnecting… | Hoisting the anchor… |
| Top card banner | Connect to your home Wi-Fi | Sail back to home waters (Wi-Fi) |
| Settings section | Soundbars | Ships |

A user-renamed input is never changed. The builder may add a few more lines in the same spirit; screen-reader meaning must stay guessable (each pirate a11y label keeps the plain word as a hint, e.g. `accessibilityHint="Mute"`).

### 2.3 Tap the Z seven times
- Seven taps on the Z in the remote header within 3 seconds show a toast: "You are now a developer." It does nothing else.
- Supporters only; not switchable (it's a secret). A non-supporter's Z stays inert.
- The toast reuses the existing `Toast` look *(builder's call: generalise `Toast` to take `{ id, text }` so it serves both device errors and this message)*.

### 2.4 Confetti on unmute
- When the perk is on and the user unmutes from the app's mute button, about 24 confetti pieces burst from the mute button and fall for ~1.2 s, drawn with React Native `Animated` views in the accent and palette colours. No new dependency.
- Not fired for unmutes from elsewhere (widget, remote, soundbar), so it never surprises.
- Skipped when the OS "reduce motion" setting is on (`AccessibilityInfo.isReduceMotionEnabled`).
- Never blocks touches (`pointerEvents="none"`).

### 2.5 Dad mode
- While on, volume is capped at 30. In the app the slider stops at 30 (its max becomes 30); dragging or tapping past it sets 30 and shows the toast "It's loud enough." once per drag.
- *Builder's call:* the cap also applies to native quick access (volume keys, widgets, notification, floating slider), because a cap the volume keys ignore isn't a cap. `QuickConfigJs` gains `volumeCap: number` (30 or 100) and native clamps every volume-up there. Without the toast outside the app.
- Turning dad mode on does not lower a volume that is already above 30. Rule everywhere: `capped(target, current, cap) = target <= current ? target : min(target, max(current, cap))`, so going down always works and going up never passes the cap (or the current level, if that is already above it).
- Refund or switching it off restores 100.

## 3. Play fixes

1. **Large screens / orientation.** `app.json` `orientation` becomes `default`. The remote, setup and settings screens centre their content in a column of at most 560 dp, so tablets, foldables and landscape phones look right. The top-card fixed height stays.
2. **R8.** Enable `enableMinifyInReleaseBuilds` and `enableShrinkResourcesInReleaseBuilds` through `expo-build-properties`. Add keep rules only where a release build on the device proves one is needed. Device smoke on the release build: discovery, connect, input switch, volume, EQ sheet, Support card with Play prices, widgets, Quick Settings tile, notification, floating slider, volume keys.
3. **Edge-to-edge deprecated APIs.** Zapbar's own code calls none of them (checked 2026-10-18). Known library sources: `react-native-screens` (`ScreenViewManager`) and React Native's status-bar module. Fix what's ours: drop any `StatusBar` prop that maps to a deprecated call, update `react-native-screens` within Expo 58's supported range if a patch fixes it. Record the remainder.
4. **Bitmap optimisation.** Find oversized bitmaps in `res/` and `assets/` and resize them to their largest shown size; load album art with `resizeMethod="resize"` so a 3000-px cover isn't decoded full-size. Record what Play still flags.
